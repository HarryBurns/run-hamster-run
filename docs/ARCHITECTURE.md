# Как устроен код

Этот файл — карта для того, кто будет добавлять в игру новое. Читать его вместо кода: здесь сказано,
где что лежит, какие правила нельзя нарушать и **как добавить** локацию, дом, занятие, действие, мебель,
мини-игру.

Игра — чистый JavaScript (ES-модули), Canvas 2D, без сборки и зависимостей. `index.html` грузит `js/main.js`.

## 1. Папки и слои

```
js/
```

**Правило слоёв.** Модуль импортирует только то, что ниже по списку, и соседей по своей папке:

```
main  →  features  →  locations, interiors  →  engine, minigames  →  ui  →  art  →  core  →  data
```

- `data/` не импортирует код (только друг друга).
- Сцены (`locations/`, `interiors/`, `engine/`) **не импортируют `features/`**. Нужно открыть окно магазина
  или начать мини-игру — сцена называет действие, его выполняет реестр (раздел 5).
- Занятия друг о друге знают мало: общение — через события (раздел 4) и реестр.

Проверка: `node dev/deps.js` — круговые импорты и нарушения слоёв (без браузера, код возврата 1 при нарушении).

## 2. Сцена

Сцена — объект с методами. Обязательны только `update` и `draw`. Подробно — в начале `core/loop.js`.

| Метод | Когда и зачем |
|---|---|
| `enter(from, params)` | вошли. `from` — имя прежней сцены (`''` при запуске). `params` — что передал `go()`; цикл добавляет `params.back` — позицию в прежней сцене. Если есть `params.pos` — сцена сама зовёт `restorePos(pos)` |
| `leave()` | уходим: снять подписки (`sub.off()`), убрать свои элементы со страницы |
| `update(dt)` | шаг логики (`dt` ≤ 0,05 с). Не вызывается, пока открыто окно |
| `draw(ctx)` | кадр; канва в CSS-пикселях, размер — `G.view.w × G.view.h` |
| `pointerDown/Move/Up(sx, sy)` | палец или мышь, CSS-пиксели экрана |
| `interact()` | клавиша E / Enter / пробел |
| `savePos()` | позиция для сохранения: объект с полем `scene`. Сцена без своего сохранения (башня, под водой, дом жителя) возвращает `back` — место снаружи |
| `restorePos(pos)` | поставить героя; `false`, если позиция не годится |
| `hud()` | кнопки HUD: `{ buttons: [{ id, icon, label, on, fn }], main: { icon, label, on, fn }, noMap, cls }` |
| `sound()` | что слышно: `{ force, day: 'town' \| 'villa', sea, rain, birds, crickets }` |
| `canHostGuests()` | (дом) можно ли впустить гостя, который пришёл сам |

**Регистрация и переходы** (`core/loop.js`):

```js
registerScene('tower', TowerScene);           // в main.js
go('tower', { back: { scene: 'world', x, y } });   // перейти; params получит enter()
go(back.scene, { pos: back });                // выйти из «внутренней» сцены туда, откуда пришли
```

- `go()` из `update()` выполняется **после** этого шага логики — старая сцена спокойно его заканчивает.
  Вне кадра (кнопка в окне) — сразу.
- После перехода цикл сам кладёт `savePos()` новой сцены в сохранение и шлёт события `scene` и `hud`.
- `main.js` и цикл не знают имён сцен: HUD, звук и сохранение спрашивают саму сцену.

**Камера** (`core/camera.js`) одна на все сцены: `setZoom` / `setTileZoom`, `setBounds`, `snap`, `follow`,
`apply(ctx)`, `toWorld`, `toScreen`, `pixelOrigin` (целые пиксели устройства — для кэша спрайтов).
**Ввод**: сцены слушателей не вешают; нажатые клавиши — `keys`, `axisX()`, `axisY()` из `core/input.js`.

## 3. Состояние и действия

- `G.state` (`core/state.js`) — всё, что уходит в сохранение. Там же `newGame`, `load`, `save`,
  `MIGRATIONS` (перенос между версиями), `repair` (починка и чистка неизвестных id), календарь.
- **Менять состояние можно только функциями из `core/actions.js`**: `spend`, `earn`, `addItem`, `addClothes`,
  `learnRecipe`, `award` (наклейка), `wear`, `setBeauty`, `addFriendPts`, `inviteGuest`, `placeFurn`,
  `moveFurn`, `stashFurn`, `plantSeed`, `setMail`, `finishTask`, `passTime`, `nextDay`, `setFlag`,
  `setDayFlag`, `recordPlay`… Остальной код состояние только читает.
- Действие само помечает сохранение изменённым; запись на диск — раз в кадр (`flush`). `save()` руками
  звать не надо. Действие окон не показывает: оно шлёт событие (`money`, `sticker`, `guests`, `look`…).
- Подсказку «Новая наклейка: …» показывает `features/album.js` по событию `sticker`; текст берётся из таблиц
  `TASKS` и `EXTRA_STICKERS`. В коде достаточно `award('x_far')` или `award('x_isles', { delay: 1200 })`.
- Нужно новое изменение состояния — **добавь функцию в `core/actions.js`** (оберни в `act`, в конце `touch()`).
- Кусочек сохранения, которым владеет одна сцена (кораблик в городе), — через `patchState(key, patch, init)`.

Автотест «состояние меняют только действия» (`dev/smoke.js`) подменяет `G.state` обёрткой и ловит любую
запись мимо `core/actions.js` — так что «быстро поправить `G.state.money` по месту» не пройдёт.

**Сохранение.** Формат не менялся (версия 1). Новое поле `homes` — мебель в других своих домах; старые
сохранения получают его при загрузке. Правило для таблиц: **id не переименовывать**; удалённый предмет
`repair()` тихо уберёт из сохранения.

## 4. События

`core/events.js`: `on(имя, fn)` → функция отписки; `emit(имя, данные)`; `scope()` — пачка подписок.

```js
const sub = scope();
enter()  { sub.on('guests', syncGuests); sub.on('wake', wake); }
leave()  { sub.off(); }
```

- Все имена перечислены в `EVENTS` с пояснениями. Подписка или `emit` с неизвестным именем — ошибка сразу.
  Новое событие сначала добавляют в `EVENTS`.
- Ежедневные задания (`features/mail.js`) считают прогресс по событиям: `buy`, `cook`, `talk`, `swim`,
  `visit`… Будущий журнал сюжетных заданий — поверх тех же событий.
- `step` — шаг логики (игровые часы в `features/sleep.js`, гость-сюрприз в `features/friends.js`).
- `wake` — утро после сна: сцена-дом ставит хомячка у кровати. Спать можно в любом доме со своей кроватью.

Чего пока нет: планировщика «через N секунд игрового времени» (ревью, A5). Отложенные подсказки по-прежнему
на `setTimeout`.

## 5. Реестр действий

`core/registry.js` связывает «что случилось в сцене» с «что при этом происходит», не давая сценам
импортировать занятия.

```js
register('cafe', (p, ctx) => openCafe(p.kind, p.title || ctx.building.name), 'кафе: { kind, title? }');

run('bank');                                   // имя
run('minigame:chef');                          // имя:аргумент  → p = { arg: 'chef' }
run({ do: 'cafe', kind: 'rest', title: '…' }); // имя и параметры → p — этот объект
run(building.act, { building, back });         // ctx — кто вызвал
```

Действие записывают **в данных**:

| Где | Поле | Пример |
|---|---|---|
| здание локации (`buildings` в описании; у города — `BUILDING_ACTS` в `locations/town.js`) | `act` | `'scene:tower'`, `{ do: 'clothes-shop', vendor: 'mall', shops: ['mall'] }` |
| особое место локации (`places`) | `act` | `'mailbox'`, `'garden:3'`, `'fish:pier'` |
| житель локации (`actors`) | `act` | `'npc:myata'` (так по умолчанию) |
| находка (`pickups`), выход (`exits`) локации | `act` | необязательно: что сделать вдобавок / вместо перехода |
| встроенный предмет дома (`built` в описании) | `act` | `'cook'` |
| мебель (`data/furniture.js`) | `act` | `'sleep'`, `'wardrobe'`, `'piano'` |
| жилец дома (`actors` в описании) | `act` | `'npc:plusha'` |
| ответ в диалоге продавца (действие `ask`) | `do` | `'minigame:swim'` |

Что зарегистрировано сейчас (полный список с описаниями — `window.__dev.listActions()`):
`scene`, `ask`, `clothes-shop`, `home-mall`, `food-mall`, `cafe`, `bank`, `salon`, `panorama`, `minigame`,
`fish`, `npc`, `guest`, `home-of`, `mailbox`, `garden`, `surprise`, `cook`, `sleep`, `wardrobe`, `fridge`, `piano`.

Неизвестное действие — ошибка в консоли (автотест её поймает), игра не падает.

## 6. Окна

- `ui/panel.js` — `openPanel({ title, tabs, render, foot, onClose })`, `message({...})` → Promise с номером
  кнопки, `confirmBox(...)` → Promise<boolean>.
- `ui/dialog.js` — `dialog({ look, name, text, options })` → Promise с номером ответа.
- `ui/toast.js` — `toast(текст, 'good')`.
- `ui/modals.js` — **слои и очередь**:
  - всё, что закрывает сцену, берёт слой: `const close = openLayer({ dim, cover })` … `close()`. Пока открыт
    хоть один слой — мир на паузе. Счётчики `G.modal / G.dim / G.cover` руками не трогать;
  - окно, которое появляется само (подарок, рецепт, итог задания, смена сезона, клад), ставят в очередь:
    `enqueue(() => message({...}), { delay: 700 })`. Очередь показывает окна по одному и только когда экран
    свободен (плюс 250 мс паузы после закрытия предыдущего окна).
- `ui/hud.js` — плашки и кнопки. Правые кнопки задаёт `main.js`, левый столбик — `scene.hud()`.

## 7. Движок домов (`engine/side/`)

Дом — **описание** (обычный объект), сцена получается так: `createSideScene(описание)`.
Полный список полей — в начале `engine/side/scene.js`. Главное:

```js
export default {
  id: 'villa',                         // имя сцены
  floors: 3, width: 1600, lift: true,  // этажи, ширина жилой части, лифт справа
  rooms: [{ id, f, x0, x1, wall, floor: 'wood' | 'tile' | 'check', win: x | null, main: true }, …],
  built: [{ type: 'door', f: 0, x: 285 }, { type: 'kitchen', f: 0, x: 1225 }, …],   // встроенные предметы
  furniture: { key: 'villa', editable: true, keepOneBed: true },   // чья мебель — см. ниже
  door: { f: 0, x: 290 },              // где стоим, войдя с улицы
  exit: 'scene:world',                 // куда ведёт дверь; без exit — назад, откуда пришли
  persist: true,                       // сцена сохраняет свою позицию
  guests: { f: 0, enterX: 300, gap: 70, first: [420, 880], roam: [250, 1540] },   // сюда ходят гости
  actors: [{ npc: 'plusha', f: 0, x: 430, roam: [230, 840], act: 'npc:plusha' }], // кто здесь живёт
  shell: { wall, roof, chimneyX, bushes },                                        // дом снаружи
};
```

**Чья мебель** (`furniture`):

- `{ key, editable, keepOneBed, start }` — своя: лежит в сохранении (`'villa'` → `state.villa`, другие ключи →
  `state.homes[key]`), есть режим «Обустроить», кладовка общая (`state.storage`). `start` — что стоит
  в начале (создаётся при первом входе).
- `{ fixed: [[id, этаж, x, y?], …], noUse }` — чужая: стоит как в описании, в сохранение не попадает,
  переставить нельзя; чужой кроватью, шкафом и холодильником пользоваться нельзя.

**Какие дома это уже покрывает** (проверено пробным домом и автотестом):

| Дом из `docs/DESIGN.md` | Как описать |
|---|---|
| дом жителя: 2–3 комнаты, мебель фиксированная, хозяин внутри | `furniture.fixed`, `actors`, без `persist` и `exit` |
| покупное жильё: своя мебель, «Обустроить», кровать для сна | `furniture: { key, editable, start }`, `persist: true`, по желанию `guests` |
| холл и номера отеля | несколько этажей + `lift: true`; номера — комнаты; стойка — `built: { type: 'zone', act }` и `actors` |
| зал своего ресторана | один этаж, `furniture.fixed` (или своя мебель), `actors` с `act`, зоны с действиями |

Чего движок **не умеет** (понадобится — дописать в движке, а не в описании): лестницы (многоэтажный дом
без лифта), комнаты разной высоты, жильцы и гости не ездят между этажами, встроенные предметы имеют
фиксированный размер рисунка, свой рисунок стен и крыши (есть только крюк `art.back / art.front` для дорисовки).
Дверь в соседнюю сцену (номер отеля из холла) делается зоной: `{ type: 'zone', f, x, w, h, act: 'scene:…' }`.

## 8. Движок локаций (`engine/topdown/`)

Локация («вид сверху»: город, а дальше лес, гора, пещеры, пустыня…) — **описание** (обычный объект), сцена
получается так: `createTopDownScene(описание)`. Полный список полей и крюков — в начале
`engine/topdown/scene.js`; пошаговый рецепт — в разделе 9 («…новую локацию»). Образцы: `locations/town.js`
(большая карта правилами), `locations/demo_meadow.js` (маленькая карта картинкой — с неё удобно списывать).

```js
export default createTopDownScene({
  id: 'forest',                        // имя сцены; оно же в сохранении позиции: { scene: 'forest', x, y }
  title: 'Лес',                        // заголовок окна карты
  rows: ['TTTT', 'T..T', …], legend: { '.': 'g', T: ['g', 'tree'] },   // карта картинкой…
  // …или правилами:  w: 72, h: 106, build(m) { m.fill(0, 0, 71, 36, 'g'); m.add('tree', 5, 5); … }
  buildings: [{ id, kind: 'house', x, y, w, h, name, icon, wall, roof, act: 'scene:hut' }],
  places:  [{ id: 'well', at: [8, 4], hit: { dx: 30, up: 50, down: 20 }, stand: [8.5, 5.5], act: 'fish:pond' }],
  actors:  [{ npc: 'myata', at: [6, 5], home: 'hut' }],
  pickups: [{ id: 'berry', at: [16, 8], icon: '🍓', give: ['ing', 'strawberry', 1] }],
  entries: { gate: { at: [11, 11.5] } },
  exits:   [{ id: 'town', area: [10, 13, 11, 13], to: 'world', entry: 'forest' }],
});
```

**Что умеет сцена сама:** ходьбу по нажатию (поиск пути) и стрелками, «дойти и сделать», вход в здания,
особые места, жителей (гуляют, вечером идут домой, ночью спят), предметы заданий и находки, переходы между
локациями, камеру, погоду и ночь, указатель цели задания, мини-карту, сохранение позиции, HUD и звук.

**Из чего собрана карта — реестр видов** (`engine/topdown/kinds.js`). Три таблицы с общими на всю игру
именами: виды клеток (`defineTiles`), предметов (`defineObjects`), зданий (`defineBuildings`).

- Общие виды лежат в `locations/common/` и появляются в реестре от `import './common/index.js'`:
  - клетки (`tiles.js`): `g` трава, `r` дорога, `y` дорожка, `s` песок, `p` плитка, `i` доски, `I` снег,
    `h` мелководье, `w` глубокая вода (плыть), `O` открытое море (нельзя), `o` бассейн, `d` пруд (зимой каток);
  - предметы (`objects.js`): `tree`, `pine`, `palm` (можно потрясти), `bush` (замедляет), `flowers`, `fenceH`,
    `fenceV`, `bench`, `fountain`, `lounger`, `umbrella`, `starfish`, `crab`, `chest`, `flag`;
  - здания (`buildings.js`): `house`, `shop`, `mall`, `tower`, `villa`.
- Свои виды локация определяет в своём файле (город — грядку, почтовый ящик, лунку; море — буйки, айсберги,
  маяк, вулкан; полянка — клевер и валун). Имя клетки — любая строка (`'clover'`), не обязательно буква.
- От вида зависит и поведение: по клетке можно или нельзя ходить (`walk`, `block`), это вода (`wet`, `swim`),
  с какой скоростью и каким звуком по ней идут (`speed`, `step`); предмет занимает клетку (`solid`) или
  замедляет (`slow` — «медленные» клетки вроде кустов). Поля — в начале `kinds.js`.

**Кэш спрайтов** (`core/sprites.js`) у всех локаций один (`SP` из `kinds.js`). Неподвижные рисунки предмет
объявляет в поле `art` и ставит вызовом `put('имя', x, y, параметр, параметр)`; здания движок кладёт в кэш сам.
Правило «спрайт 1:1 на целых пикселях» держится на `cam.setTileZoom` (в `scene.js`) и `cam.pixelOrigin()`
(в `render.js`) — их не трогать. Размер клетки `T = 48` — один на все локации. Земля в кэш не попадает:
клетки рисуются заново каждый кадр (их `draw` должен быть дешёвым — пара прямоугольников и линий).

**Поиск пути** (`path.js`) — чистые функции: кто где может пройти, говорит `pass(tx, ty)`, который передают
в вызов. Готовые: `map.foot` (герой пешком), `map.dry` (жители — только по суше). Свой способ передвижения —
поле героя `sc.p.ride = { speed, pass, step, moved, draw, drop }`: пока оно задано, герой ходит по его
правилам (так сделан кораблик в `sea.js`). Глобальных переключателей режима больше нет.

**Особые места** (`places`) — данные: где место (предмет с зоной нажатия `at + hit`, клетка `cell`,
прямоугольник `area` или все клетки вида `tile`), куда встать (`stand`), когда оно работает (`when`),
какое действие из реестра выполнить (`act`), как показать на мини-карте (`map`). Почтовый ящик, грядки, лунка,
пруд и пирс города записаны так (`PLACES` в `town.js`) — координат в коде движка нет.

**Переходы.** У локации есть точки входа (`entries`) и выходы (`exits`): хомячок наступил на клетку выхода →
`go(to, { at: entry })` → появился в точке входа другой локации. Выход можно держать закрытым (`off: true`
или `when()`), открыть — `getLocation('world').exit('forest').off = false`. Вход в дом — как раньше, зданием
с `act: 'scene:<дом>'`. Кто пришёл из сцены, названной во входе (`from: 'villa'`), встаёт на этот вход.

**Несколько локаций** (`scene.js`): `locations` — все по имени сцены, `getLocation(имя)`,
`currentLocation()` — где хомячок сейчас (пока он в доме — та, что снаружи), `homeLocation()` — главная
(`home: true`, город). Занятия берут локацию отсюда, а не импортируют город: окно карты (`features/map.js`)
показывает текущую локацию, почта (`features/mail.js`) разбрасывает предметы задания в локации задания
(`loc` в задании; без него — в главной) по её зонам (`zones`).

**Позиция в сохранении** — `{ scene: <id локации>, x, y }`. У города id — `'world'` (так записано в старых
сохранениях — **не менять**). Если позиция оказалась в стене (карту перерисовали), хомячок встанет на ближайшую
свободную клетку, а если её нет — на вход `start`.

**Части и крюки.** То, что у локации уникально, пишут функциями-крюками в описании: `built`, `enter`, `tap`,
`tapThing`, `interact`, `near`, `idle`, `update`, `surface`, `ground`, `things`, `over`, `overlay`, `miniMap`,
`target`, `buttons`. Большую самостоятельную механику выносят в «часть» — объект с теми же крюками в списке
`parts`. Так подключено море: `sea.js` → `createSea(настройки)` даёт кораблик, острова, морских жителей,
буйки и ныряние; город зовёт `sea.buildGround(m)` и `sea.buildObjects(m)` в своих правилах карты.

**Порядок вызовов `Math.random` в `update`** сохранён прежним (герой → жители → погода → море): от него
зависят снимки «до/после» (`dev/shots.js`). Карта строится при первом обращении к локации (вход, окно карты,
`randomSpots`) — тогда же жители получают случайную паузу.

Чего движок **не умеет** (понадобится — дописать в движке, а не в описании):

- клетка всегда 48 единиц, карта — прямоугольник; «этажей» и мостов над дорогой нет;
- карта после постройки не меняется (нельзя на лету заменить клетку или поставить предмет; закрытый проход
  делают выходом с `off`, сезонное — функцией `walk` у вида клетки или `when` у места);
- жители гуляют возле своего места и ходят домой; расписания по часам и походов в другую локацию нет;
- способ передвижения (`ride`) при переходе в другую локацию не переносится: кораблик живёт в море города
  и хранит одно место в сохранении (`state.boat`) — для моря другой локации нужен свой ключ (`key` в настройках
  `createSea`);
- общей «карты мира» со всеми локациями нет: окно карты показывает одну, текущую;
- звёздочка задания показывает цель только внутри своей локации (до выхода в нужную локацию не ведёт).

## 9. Как добавить…

### …новую локацию

Образец для списывания — `js/locations/demo_meadow.js` (110 строк, в нём есть всё перечисленное ниже).
Координаты в описании — **в клетках**: `[5, 9]` — клетка; там, где нужна точка (`stand`, `entries`, `mark`),
дробная часть — место внутри клетки: `15.5` — середина клетки 15.

1. **Файл и имя.** Создай `js/locations/<имя>.js`:

   ```js
   import { T, OUT, put, defineTiles, defineObjects, createTopDownScene } from '../engine/topdown/index.js';
   import './common/index.js';                    // общие клетки, предметы и здания
   export default createTopDownScene({ id: 'forest', title: 'Лес', … });
   ```

   `id` — имя сцены; оно попадает в сохранение, поэтому **придумай один раз и не меняй**.
2. **Карта.** Маленькую удобнее рисовать строками: `rows: ['TTTT', 'T..T', …]` и `legend: { '.': 'g',
   T: ['g', 'tree'], M: ['moss', 'mushroom', { v: 1 }] }` — символ → вид клетки и, если надо, предмет на ней.
   Большую — правилами: `w, h, base: 'g'` и `build(m)`, где `m.fill(x0, y0, x1, y1, 'r')`, `m.set(x, y, 'g')`,
   `m.add('tree', x, y, { v: 2 })`, `m.at(x, y)`; для случайной зелени бери `seeded(число)` из `core/util.js`,
   а не `Math.random` (образец — `build` в `town.js`). Край карты обнеси деревьями или водой.
   `bg` — цвет за краем карты.
3. **Свои клетки** — `defineTiles({ moss: { map: '#5a8', step: 'step', draw(ctx, x, y, tx, ty, env) { … } } })`.
   `draw` закрашивает квадрат `T + 1` от точки `(x, y)`; сезон — `env.season`, время — `env.t`. `map` — цвет
   на мини-карте. Нельзя ходить — `walk: false`; вода — `wet: true` (и `swim`, если хомячок в ней плывёт);
   своя скорость — `speed`. Буквы общих клеток заняты (раздел 8) — называй свои словами.
4. **Свои предметы** — `defineObjects({ mushroom: { solid: true, art: { mushroom: [[-20, -30, 20, 16],
   (ctx, season) => { …рисуем вокруг точки (0, 0) — центра клетки… }] }, draw(ctx, o, env) { put('mushroom',
   o.x, o.y, env.season); } } })`. В `art` — только неподвижное: рамка `[x0, y0, x1, y1]` с запасом и функция
   рисования; всё, от чего зависит вид (сезон, вариант `o.v`, «горит свет»), передавай параметрами `put` —
   они входят в ключ кэша. Шевелится — либо сдвигай готовый спрайт (`put('crown', o.x + Math.sin(env.t) * 1.5,
   o.y)`), либо рисуй линиями поверх после `SP.world()`. Рамка мала — в консоли будет предупреждение, автотест
   его ловит. `solid: true` — на клетку не встать; `slow: 0.5` — идут вдвое медленнее; `flat: true` — лежит
   под ногами; `tap` + `use(sc, o)` — можно нажать (образец — пальма в `common/objects.js`).
5. **Здания** — `buildings: [{ id, kind, x, y, w, h, name, icon, wall, roof, act }]`: `x, y, w, h` — «пятно»
   в клетках, дверь снизу по центру, хомячок встаёт под ней. `act` — что происходит на входе:
   `'scene:<дом>'` (дом — раздел 9, «…новый дом»), `'minigame:<id>'`, `{ do: 'ask', … }` и т. д.
   Нужен свой вид здания — `defineBuildings({ hut: { paint(ctx, b, snow, lit) { … } } })`, рисуется
   в координатах мира от `b.x * T, b.y * T` (образцы — `common/buildings.js`).
6. **Жители** — `actors: [{ npc: 'shishkin', at: [6, 5], home: 'hut' }]`. `npc` — id из `data/npcs.js`
   (нового жителя сначала добавь туда: имя, внешность, реплики). Гуляет возле `at`, с 19:00 идёт к двери
   здания `home` (или в клетку `home: [x, y]`), ночью его нет (`always: true` — есть всегда). Подошёл
   хомячок — выполняется `act` (по умолчанию `'npc:<id>'` — разговор).
7. **Особые места** — `places: [{ id, …, act }]`. Где: `at: [x, y]` + `hit: { dx, up, down }` (нажимают
   на предмет, который ты поставил на эту клетку) либо `cell: [x, y]`, `area: [x0, y0, x1, y1]`, `tile: 'вид'`
   (нажимают на клетки). `stand: [x, y]` — куда хомячок встанет; `when: () => …` — когда место работает.
   `act` — действие из реестра (раздел 5): готовое (`'fish:pond'`, `'panorama'`, `'minigame:<id>'`,
   `{ do: 'cafe', … }`) или новое — тогда зарегистрируй его в своём файле `features/` («…новое действие»).
   Совсем простое можно написать на месте: `use(sc) { toast('Ку-ку!'); }` вместо `act`.
8. **Переходы.** В обеих локациях нужны вход и выход:

   ```js
   // в лесу                                              // в городе (locations/town.js)
   entries: { gate: { at: [11, 11.5] } },                 entries: { …, forest: { at: [2.5, 24.5] } },
   exits: [{ id: 'town', area: [10, 13, 11, 13],          exits: [{ id: 'forest', area: [0, 24, 0, 25],
            to: 'world', entry: 'forest' }],                       to: 'forest', entry: 'gate', off: true }],
   ```

   `area` — клетки, наступив на которые хомячок уходит; вход ставь **рядом с выходом, но не на его клетки**.
   Закрытое до задания место: `off: true`, а открывает его занятие — `getLocation('world').exit('forest').off =
   false` при загрузке и при выполнении задания (или `when: () => !!G.state.flags.forestOpen` прямо в описании).
   Переход «через действие» (канатная дорога с вопросом «Едем?») — особое место или здание с `act`, которое
   зовёт `go('mountain', { at: 'station' })`.
9. **Собираемое.** Находки локации — `pickups: [{ id, at: [x, y], icon: '🍄', give: ['ing', 'mushroom', 1],
   text: '+1 🍄 Гриб' }]`: лежат на земле, подбираются на ходу, утром появляются снова (`once: true` — один раз
   за игру). `give` — `[сумка, id, сколько]` для `addItem` (сумки: `ing`, `seeds`, `dishes`, `storage`); сам
   предмет сначала добавь в таблицу `data/`. Каждая находка шлёт событие `find { loc, id }` — по нему
   считают задания. Чтобы находки каждый день лежали в новых местах, в крюке `enter` вызови
   `sc.setPickups(sc.randomSpots('glade', 5, G.state.day).map((s, i) => ({ id: 'm' + i, at: [s.x, s.y], … })))`. Предметы ежедневного задания «собери»: опиши зону `zones: { glade: { x: [1, 18],
   y: [1, 12], tiles: ['g'] } }`, а в задании (`data/tasks.js`) укажи `loc: '<id локации>'` и `zone: 'glade'`.
10. **Мини-карта и «дойти до места».** Окно карты само показывает текущую локацию: землю красит полем `map`
    видов клеток, деревья — полем `map` видов предметов, здания — их цветом и значком. Кнопки «дойти» получают
    здания с `name`, точки `spots: { glade: { at: [8.5, 6.5], label: '🌼 Поляна' } }` и особые места
    с `map: { icon: '🎣', at: [51, 46], label: '🎣 Пирс' }`. Что-то своё на карте — крюк `miniMap(ctx, sc, k)`
    (`k` — пикселей на клетку). Звёздочка задания — крюк `target(sc)` → `{ x, y, icon }`; точку по имени
    даёт `sc.spot(id)` (образец — `target` в `town.js`).
11. **Свет, погода, звук.** Вечная зима на вершине — `season: 'winter'` (деревья и земля рисуются зимними
    в любой месяц). Под землёй или под крышей — `sky: false` (ни погоды, ни ночи). Пещера с фонариком:

    ```js
    sky: false,
    overlay(ctx, sc, w, h) {                       // поверх кадра, в экранных координатах
      const s = sc.cam.toScreen(sc.p.x, sc.p.y - 30);
      spotlight(ctx, w, h, s.x, s.y, 170);         // темнота с кругом света; spotlight — из engine/topdown/index.js
    },
    ```

    `sound: (sc) => ({ day: 'town', sea: 0, rain: 1, birds: true, crickets: true })` — что слышно.
12. **Уникальная механика** (кататься на верблюде, светлячки ночью, белка-меняла) — крюками в описании:
    `update(sc, dt)`, `things(sc, add, view)` — нарисовать своё в общем порядке «дальше → ближе»,
    `tapThing(sc, w, tx, ty)` — нажали на своё существо, `buttons(sc)` — кнопки HUD. Большое — отдельным файлом-
    «частью» (`parts: [часть]`), образец — `locations/sea.js`. Состояние меняй только действиями (раздел 3).
13. **Зарегистрируй** в `js/main.js`: `for (const loc of [town, demoMeadow, forest]) registerScene(loc.name, loc);`.
14. **Проверь.**
    - В консоли браузера: `__dev.go('forest')`, сцена — `__dev.locations.forest` (`.map`, `.p`, `.npcs`,
      `.debugTeleport(x, y)`, `.debugSprites().clipped` — должно быть пусто, `.walkTo(x * 48, y * 48, true)`).
    - Добавь шаги в `dev/smoke.js` по образцу «пробная локация: …» и «переход между локациями: …» (вход,
      ходьба, особое место, находка, житель, карта, сохранение и загрузка позиции, переход туда и обратно).
    - Добавь группу снимков в `dev/shots.js` по образцу `meadow`.
    - `node dev/smoke.js <url>`, `node dev/deps.js`, `node dev/bench.js <url>`; снимки «до/после» города не
      должны измениться, если ты его не трогал.

Как **перерисовать или переставить** то, что уже есть в городе:

- вид клетки или предмета — его `draw` / `art` в `locations/common/tiles.js` и `objects.js` (или в `town.js`,
  `sea.js` — для своих); поменял рисунок предмета — проверь, что он помещается в рамку
  (`debugSprites().clipped`); цвета земли по сезонам — `PAL` в `tiles.js`, листвы — `leafCol` в `objects.js`,
  цвет клетки на мини-карте — её поле `map`. Клетка закрашивает квадрат `T + 1` (с нахлёстом в пиксель,
  иначе между клетками видны швы) и рисуется каждый кадр: новая земля с плавными переходами между видами
  потребует кэша земли кусками — это доработка `render.js` (одно место: цикл по клеткам в `drawFrame`);
- здания: рисунки по видам — `locations/common/buildings.js`; где какое стоит, как называется и какого оно
  цвета — таблица `BUILDINGS` в `town.js` (`x, y, w, h` в клетках). Переставил дом — проверь рядом дороги
  в `build` (`fill(…, 'r')`), места жителей (`HANG`), зону предметов заданий (`zones`) и что дверь
  (снизу по центру) выходит на свободную клетку;
- особые места и всё, что к ним привязано, — в `PLACES` (ящик, грядки, пирс, пруд), бассейны — `POOLS`,
  забор двора — `YARD`; острова, буйки и стоянка кораблика — `WORLD_SEA` в `sea.js`.

### …новый дом

1. Создай `js/interiors/<имя>.js` с описанием (образцы: `villa.js`, `demo_house.js`).
2. В `js/main.js` добавь его в список домов: `for (const house of [villa, demoHouse, новый]) …`.
3. Дай в него вход. Из локации: у здания (`buildings` в её описании; у города — таблица `BUILDING_ACTS`
   в `locations/town.js`) напиши `act: 'scene:<id>'` — локация сама передаст `back` (место у двери),
   и дверь дома вернёт туда же.
4. Нужен встроенный предмет, которого нет, — добавь тип в `engine/side/fixtures.js` (размер зоны, `use` или
   `act`, рисунок `back`/`front`). Нужна просто «кнопка» в комнате — `{ type: 'zone', f, x, w, h, act }`.
5. Если дом покупной — заведи действие «купить» в занятии (`features/`), а ключ мебели придумай один раз
   и не меняй: он попадает в сохранение.
6. Добавь шаг в `dev/smoke.js` (образец — шаги «пробный дом»), проверь `node dev/smoke.js`.

Посмотреть пробный дом: в консоли браузера `__dev.go('demo_house')`; «своё жильё» из того же описания —
`__dev.registerScene('demo_flat', __dev.createSideScene(__dev.demoOwn)); __dev.go('demo_flat')`.

### …новое занятие или окно

1. Создай `js/features/<занятие>.js`. Внутри — функция, которая открывает окно (`openPanel`, `message`,
   `dialog`), меняет состояние **только действиями** и шлёт события, если это важно заданиям.
2. Зарегистрируй действие: `register('market', (p, ctx) => openMarket(p), 'рынок: …')`.
3. Добавь строку `export * from './<занятие>.js';` в `features/index.js` (иначе файл не загрузится).
4. Привяжи к месту: у здания, предмета или жильца напиши `act: 'market'`. Кнопка в HUD — в `main.js` (`initHud`).
5. Занятию нужна сцена (переместить героя, показать радость) — не импортируй сцену, а пошли событие
   (как `happy`, `guests`, `wake`) или вызови `go()`.

### …новое действие в реестр

`register(имя, (p, ctx) => …, 'описание')` в том файле `features/`, которому оно принадлежит. Имя — без
двоеточия (двоеточие отделяет аргумент). `p.arg` — короткий аргумент, остальные поля `p` — из объекта
`{ do: имя, … }`. `ctx` — что передала сцена: `{ building, scene, back }` у здания локации, `{ scene, place }`
у особого места, `{ scene, actor }` у жителя или жильца, `{ scene, item }` у мебели, `{ scene, fixture }`
у встроенного предмета.

### …новый предмет мебели

1. Строка в `js/data/furniture.js`: `F(id, kind, название, цена, ширина, высота, { act, c, cat, wall, layer, shop })`.
   `shop: 'gift'` — только в подарок; `cat` — раздел магазина.
2. Если `kind` новый — функция рисования в таблице `D` в `js/art/furniture.js`
   (начало координат: у напольных — середина нижнего края, у настенных — центр).
3. Если `act` новый: происходит в комнате (сел, включил) — строка в таблице `USE` в `engine/side/items.js`;
   открывает окно — действие с таким же именем в реестре.
4. Значок в магазине и кладовке получится сам (`ui/icons.js`).

### …новую мини-игру

1. `js/minigames/<игра>.js`: `export default { id, title, icon, howTo, start(host) }`. `start` строит игру
   в `host.root`, в конце зовёт `host.finish({ stars: 1..3, text, extra })`, возвращает `{ stop() }`.
   Рамка, заставка, звёзды, `host.canvas()`, `host.sfx`, `host.drawHamster` — в `minigames/host.js`.
2. Строка в `LOADERS` в `minigames/host.js`; название для альбома — в `MG_NAMES` (`features/minigames.js`).
3. Мини-игра **не импортирует `features/`**. Нужно что-то от занятий (шкаф, оценка наряда) — передай через
   `host.info`: таблица `TOOLS` в `features/minigames.js` (образец — «Показ мод»).
4. Запуск: `act: 'minigame:<id>'` у здания или `do` у ответа в диалоге. Проверка отдельно от игры:
   `dev/minigame.html?g=<id>`.

### …новую сцену не «дом»

Объект с методами из раздела 2 (образцы: `interiors/tower.js`, `interiors/dive.js`), камера —
`new Camera()`, регистрация в `main.js`. Позицию «откуда пришли» бери из `params.back` и возвращай её
в `savePos()`, если своей позиции в сохранении у сцены нет.

## 11. Что дальше

Каркас готов для этапов 4–5 из `docs/DESIGN.md`: дома строятся описаниями для «движка домов» (раздел 7),
места — описаниями для «движка локаций» (раздел 8). Что остаётся сделать по мере надобности:

- **Новые локации** (лес, гора, пещеры, пустыня, джунгли, секретный пляж, удалённый остров, отель) — по рецепту
  из раздела 9. Выход в пробную полянку в городе уже описан (`exits` в `town.js`, закрыт) — как образец того,
  как будет выглядеть тропа в лес.
- **Карта мира.** Окно карты показывает одну локацию. Когда локаций станет несколько, понадобится общий вид
  (силуэты закрытых мест с замочком) и звёздочка задания, которая ведёт к выходу в нужную локацию: у каждой
  локации есть `exits` и `sc.spot(id)` — этого достаточно, чтобы построить путь «через выход».
- **Замки на местах.** Открыто ли место, должно лежать в сохранении (флаг задания), а выход — читать его
  (`when` в описании выхода). Сейчас у выхода есть только поле `off` в памяти.
- **Задания в других локациях.** `features/mail.js` уже умеет разбросать предметы в локации задания (`loc`,
  `zone` в `data/tasks.js`) и помечает их именем локации; будущий журнал заданий — поверх событий (раздел 4),
  находки шлют событие `find`.
- **Кораблик в другую локацию** (джунгли, удалённый остров): море — часть локации (`createSea(настройки)`
  в `sea.js`), но кораблик хранит одно место (`state.boat`) и при переходе не «переезжает». Для причала
  в другой локации — выход на клетках воды и своё место кораблика там (`key` в настройках моря).
- **Праздники** — слой поверх локации («с такого-то по такой-то день добавить эти предметы»): карта после
  постройки не меняется, так что слой — это крюки `things` / `ground` в отдельной «части» (`parts`) либо
  доработка движка (перестроить карту при смене дня).
- Планировщика «через N секунд игрового времени» по-прежнему нет (ревью, A5): отложенные подсказки —
  на `setTimeout`.
