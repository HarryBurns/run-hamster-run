# Как устроен код

Этот файл — карта для того, кто будет добавлять в игру новое. Читать его вместо кода: здесь сказано,
где что лежит, какие правила нельзя нарушать и **как добавить** локацию, дом, занятие, действие, мебель,
мини-игру.

Игра — чистый JavaScript (ES-модули), Canvas 2D, без сборки и зависимостей. `index.html` грузит `js/main.js`.

**Правило слоёв.** Модуль импортирует только то, что ниже по списку, и соседей по своей папке:

```
main  →  features  →  locations, interiors  →  engine, minigames  →  ui  →  art  →  core  →  data
```

- `data/` не импортирует код (только друг друга).
- Сцены (`locations/`, `interiors/`, `engine/`) **не импортируют `features/`**. Нужно открыть окно магазина
  или начать мини-игру — сцена называет действие, его выполняет реестр (раздел 5).
- Занятия друг о друге знают мало: общение — через события (раздел 4) и реестр.

Проверка: `node dev/deps.js` — круговые импорты и нарушения слоёв (без браузера, код возврата 1 при нарушении).

## 2. Сцена

Сцена — объект с методами. Обязательны только `update` и `draw`. Подробно — в начале `core/loop.js`.

| Метод | Когда и зачем |
|---|---|
| `enter(from, params)` | вошли. `from` — имя прежней сцены (`''` при запуске). `params` — что передал `go()`; цикл добавляет `params.back` — позицию в прежней сцене. Если есть `params.pos` — сцена сама зовёт `restorePos(pos)` |
| `leave()` | уходим: снять подписки (`sub.off()`), убрать свои элементы со страницы |
| `update(dt)` | шаг логики (`dt` ≤ 0,05 с). Не вызывается, пока открыто окно |
| `draw(ctx)` | кадр; канва в CSS-пикселях, размер — `G.view.w × G.view.h` |
| `pointerDown/Move/Up(sx, sy)` | палец или мышь, CSS-пиксели экрана |
| `interact()` | клавиша E / Enter / пробел |
| `savePos()` | позиция для сохранения: объект с полем `scene`. Сцена без своего сохранения (башня, под водой, дом жителя) возвращает `back` — место снаружи |
| `restorePos(pos)` | поставить героя; `false`, если позиция не годится |
| `hud()` | кнопки HUD: `{ buttons: [{ id, icon, label, on, fn }], main: { icon, label, on, fn }, noMap, cls }` |
| `sound()` | что слышно: `{ force, day: 'town' \| 'villa', sea, rain, birds, crickets }` |
| `canHostGuests()` | (дом) можно ли впустить гостя, который пришёл сам |

**Регистрация и переходы** (`core/loop.js`):

```js
registerScene('tower', TowerScene);           // в main.js
go('tower', { back: { scene: 'world', x, y } });   // перейти; params получит enter()
go(back.scene, { pos: back });                // выйти из «внутренней» сцены туда, откуда пришли
```

- `go()` из `update()` выполняется **после** этого шага логики — старая сцена спокойно его заканчивает.
  Вне кадра (кнопка в окне) — сразу.
- После перехода цикл сам кладёт `savePos()` новой сцены в сохранение и шлёт события `scene` и `hud`.
- `main.js` и цикл не знают имён сцен: HUD, звук и сохранение спрашивают саму сцену.

**Камера** (`core/camera.js`) одна на все сцены: `setZoom` / `setTileZoom`, `setBounds`, `snap`, `follow`,
`apply(ctx)`, `toWorld`, `toScreen`, `pixelOrigin` (целые пиксели устройства — для кэша спрайтов).
**Ввод**: сцены слушателей не вешают; нажатые клавиши — `keys`, `axisX()`, `axisY()` из `core/input.js`.

## 3. Состояние и действия

- `G.state` (`core/state.js`) — всё, что уходит в сохранение. Там же `newGame`, `load`, `save`,
  `MIGRATIONS` (перенос между версиями), `repair` (починка и чистка неизвестных id), календарь.
- **Менять состояние можно только функциями из `core/actions.js`**: `spend`, `earn(n, источник)`, `addItem`, `addClothes`,
  `learnRecipe`, `award` (наклейка), `wear`, `setBeauty`, `addFriendPts`, `inviteGuest`, `placeFurn`,
  `moveFurn`, `stashFurn`, `plantSeed`, `setMail`, `finishTask`, `passTime`, `nextDay`, `setFlag`,
  `setDayFlag`, `recordPlay`, `takeQuest`, `questCount`, `finishQuest`, `openLand`… Остальной код состояние только читает.
- Действие само помечает сохранение изменённым; запись на диск — раз в кадр (`flush`). `save()` руками
  звать не надо. Действие окон не показывает: оно шлёт событие (`money`, `sticker`, `guests`, `look`…).
- Подсказку «Новая наклейка: …» показывает `features/album.js` по событию `sticker`; текст берётся из таблиц
  `TASKS` и `EXTRA_STICKERS`. В коде достаточно `award('x_far')` или `award('x_isles', { delay: 1200 })`.
- Нужно новое изменение состояния — **добавь функцию в `core/actions.js`** (оберни в `act`, в конце `touch()`).
- Кусочек сохранения, которым владеет одна сцена (кораблик в городе), — через `patchState(key, patch, init)`.

Автотест «состояние меняют только действия» (`dev/smoke.js`) подменяет `G.state` обёрткой и ловит любую
запись мимо `core/actions.js` — так что «быстро поправить `G.state.money` по месту» не пройдёт.

**Сохранение.** Версия 5. Версия 2 — новая экономика; версия 3 — жильё, заведения и гости у жителей (раздел 11);
версия 5 — журнал заданий: поля `quests`, `lands`, `finds` (раздел 13; перенос v4 → v5 — `MIGRATIONS[4]`: пусто,
отметка `flags.questsEarly` — задание Мяты сразу, а не со второго дня; образец `dev/saves/v5.json` — Ириска
с гербарием в работе);
версия 4 — болезнь: поля `sick` (`{ since, cause }` или `null`) и `immuneUntil` (с какого дня снова можно заболеть);
перенос v3 → v4 — `MIGRATIONS[3]`: здорова, `immuneUntil = day + 3` (первые дни после обновления, как в новой игре).
Перенос v1 → v2 — `MIGRATIONS[1]` в `core/state.js`: деньги
становятся 20 000, вещи, мебель, друзья и наклейки не трогаются, ставится отметка `flags.bankLetter` — по ней
`features/bank.js` один раз показывает письмо банка. Новые поля (их создаёт `repair()`): `earned`, `ledger`
(доход по источникам и траты за сегодня и вчера), `pearlsSold`. Образцы — `dev/saves/v1.json`, `v2.json`, `v3.json`,
`v4.json` (простуженная Ириска).
Поле `homes` — мебель в других своих домах. Правило для таблиц: **id не переименовывать**; удалённый предмет
`repair()` тихо уберёт из сохранения.

**Деньги.** Все числа баланса — в `data/economy.js`: стартовый капитал, зарплаты (`JOBS`), награды за задания,
цены (`PRICES` — таблицы одежды, мебели, еды и салона берут цены оттуда), рынок (`MARKET`). Правишь баланс —
правь только этот файл и запусти `node dev/balance.js`: он печатает «сколько можно заработать за день и что
сколько стоит» и падает, если у чего-то нет цены или появился «вечный двигатель» (купить → продать дороже).
- **Сезоны урожая** — одна таблица `HARVEST_MONTHS` в `data/seasons.js`: продукт → месяцы сезона (0 — январь;
  продукта в таблице нет — он есть круглый год). Рядом функции `ripeIn(id, месяц)`, `seasonsOf(id)`,
  `whenRipe(id, значки)` («весной», «осенью 🍂 и зимой ❄️»). Из неё берут сезон все: растения в городе
  (`common/plants.js` — есть ли плод), огород (`features/garden.js`: `canSow(семена, месяц)` — культуру сажают
  только в её сезон; посаженное дорастает), продукты (`data/food.js`: поля `months` и `seasons`), задание
  «Кокосовый день» (`data/tasks.js`) и расчёт баланса. Продукт, который в магазине круглый год, но растёт на дереве
  (яблоки), в `HARVEST_MONTHS` не пишут: его месяцы сбора — `PICK_MONTHS` там же (растения и `dev/balance.js` берут
  `pickIn(id, месяц)`; цена в ТЦ от этого не меняется). С Э1 в таблице записаны и сезоны огорода (салат — зима
  и весна, клубника — весна и лето, помидоры — лето, морковка — лето и осень, подсолнухи и тыква — осень).
- **Сезоны вещей** (одежда, мебель, украшения) — в том же файле `data/seasons.js`, таблица `WARE_MONTHS`:
  коллекция → месяцы сезона (`cold` — осень и зима, `hot` — весна и лето, `rain` — весна и осень, `spring`,
  `autumn`, праздничные `newyear` и `halloween` — месяц праздника ± месяц). Вещь называет свою коллекцию полем
  `season` в `data/clothes.js` или `data/furniture.js`; поля нет — продаётся круглый год. Рядом
  `warePhase(коллекция, месяц)` → `'new' | 'in' | 'last' | 'off' | null` и `whenWare(коллекция)` («осенью 🍂
  и зимой ❄️», «к Новому году 🎄»). Новая сезонная вещь — одно поле в её строке; новая коллекция — строка
  в `WARE_MONTHS`. Вторую систему сезонов не заводить (теги `tags` у одежды — для показа мод и реплик друзей).
  Сколько даёт сбор — `GATHER` в `economy.js` (`n` — плодов с растения за раз, `max` — сколько таких растений
  на карте самое большее; автотест сверяет с картой, `dev/balance.js` считает сбор и огород по сезонам).
- **Сезонные цены продуктов.** Сезонный продукт — тот, у кого есть сезон в таблице и цена в `PRICES.ing`
  (`isSeasonal(ing)`): огород, сбор, южные фрукты. `PRICES.ing` — обычная цена; сколько продукт стоит сейчас —
  `buyPrice(ing, месяц)` (в сезон × `SEASONAL.inPrice`, не в сезон × `SEASONAL.offPrice`), сколько за него даёт
  рынок — `sellPrice(ing, месяц)` (`MARKET.shopShare` самой низкой цены покупки; не в сезон × `SEASONAL.offSell`).
  Окна цену сами не считают — берут эти функции (`data/food.js`).
- **Ассортимент дня — общий механизм для всех магазинов** («товар бывает не каждый день и понемногу»):
  - `data/stock.js` — чистый расчёт: `stockOn(день, 'магазин:товар', правило)` → сколько штук привезли (0 — нет,
    `Infinity` — сколько угодно), `nextStockIn(…)` → через сколько дней привезут. Правило — `{ days, of, min, max }`:
    в каждом отрезке из `of` дней товар бывает в `days` из них, от `min` до `max` штук; `null` — есть всегда.
    Зависит только от номера дня и ключа, поэтому перезагрузка страницы прилавок не меняет. Сами правила — числа
    баланса: `STOCK` в `economy.js`.
  - `features/stock.js` — то же с учётом сохранения: `stockToday(магазин, товар, правило)` →
    `{ state: 'ok' | 'none' | 'sold', left, limited }`, `takeStock(st, n)` (купленное сегодня лежит в отметках
    дня `dayFlags.bought` и утром сбрасывается само — версия сохранения не менялась), `comeBack(…)` («завтра»,
    «послезавтра»), `leftText(st)` («Осталось 2 шт.»), `awayCard(…)` — серая карточка «сегодня нет / раскупили»:
    товар не прячем, а объясняем, почему его нет и когда будет.
  - Какое правило у какого товара, решает его таблица: у продуктов — `foodRule(ing, месяц)` и `dishRule(блюдо)`
    в `data/food.js`. Всё про продукт «сегодня» (цена, сезон, ТЦ, рынок, где взять) собирает
    `features/pantry.js` — им пользуются ТЦ «Вкусный», рынок, окно готовки и письма.
  - **Вещи (одежда, мебель, украшения)** — `data/wares.js` (чистый расчёт) и `features/wares.js` (для окон).
    Правило вещи — `wareRule(вещь, месяц)`: сезонная в сезон — `null` (всегда), не в сезон — `WARES.off`
    (один день из трёх); круглогодичная — по полю `stock` в таблице: `'delivery'` → `WARES.delivery` (два дня
    из трёх), `'special'` → `WARES.special` (через день), без поля — всегда. Цена — `warePrice(вещь, месяц)`:
    в последний месяц сезона × `WARES.sale`. Ключ прилавка — `'магазин:вещь'` (`mall`, `boutique`, `beach`,
    `home`, `market` — поле `shop` вещи); `wareOn(вещь, день)` — есть ли на витрине, `shopWares(магазин)` —
    все вещи магазина. Вещицы рынка — `trinketsOn(день)`: `pickOn(день, магазин, список, n)` из `data/stock.js`
    («сегодня привезли n товаров из списка») среди тех, кого сегодня привозят. Окнам хватает
    `features/wares.js`: `wareToday(вещь)` → `{ season, price, sale, here, fresh }`, `wareBadge` (значок),
    `warePriceTag` (ценник со скидкой), `wareAwayCard` (серая карточка), `wareOrder` (порядок на витрине),
    `wareNote` (строка «Сегодня привезли… Завтра привезут…»), `waresHere(магазин)`, `trinketsToday()`.
    Ими пользуются `wardrobe.js` (магазины одежды), `shops.js` (ТЦ «Уютный дом»), `market.js`, `mail.js`
    (подсказки в письмах; «Обновка» приходит, только если есть что купить) и `gifts.js` (праздничные подарки —
    около праздника). Состояние не менялось: вещи покупают по одной, «сколько осталось» не нужно.
    `dev/balance.js` проверяет разметку, минимум выбора в каждом магазине (`WARES.minChoice`) и распродажу.
- Получить монеты — `earn(n, источник)`; источник (`work`, `market`, `task`, `gift`, `other`) попадает
  в учёт для банка. Новый источник (доход от бизнеса) — строка в `INCOME_SOURCES` и `earn(n, 'business')`.
- Потратить — `buy(cost, что)` из `features/purchase.js` (сам скажет «не хватает N монет»); в карточке товара —
  `priceTag(cost)` и `buyBtn(текст, cost, fn)`: по ним видно, хватает ли монет.
- «Раз в день» (оплаченные смены, кошелёк торговца) лежит в `dayFlags` и сбрасывается утром само.
- Отклик «+350 / −120» рядом с числом монет появляется сам по событию `money` (`ui/coins.js`).

**Болезнь (Ф1).** Правила игры — `docs/GDD.md`, 6.10. Где что лежит:

- `data/health.js` — чистые таблицы и расчёт: `HEALTH` (шанс «просто так», сколько дней болеет, иммунитет, первые дни,
  во сколько медленнее ходит, через сколько минут на холоде подсказка и неосторожность), `CARELESS` (неосторожности
  дня — прибавка к шансу и тексты), `nightHealth({ day, sick, immuneUntil, careless, key })` — что случится ночью
  (`{ fall: причина }`, `{ recover: true }` или `{}`; жребий — `dayRoll` из `data/stock.js` по номеру дня и имени,
  поэтому перезагрузка решение не меняет), `dressedWarm(outfit)`, `dressedForRain(outfit)`, `coldDay(day)`,
  `WARM_DRINKS`, `taskNeedsHealth(задание, JOBS)`, `SICK_TEXT` (подсказки для сцен). Цена приёма — `DOCTOR_FEE`

  тёплое питьё — `dayFlags.sickTea`; утром они сбрасываются сами.
- Чтение — `core/state.js`: `isSick()`, `canSwim()`, `walkK()` (множитель шага: сцены умножают на него скорость
  ходьбы), `sneezePhase()` (чих для позы; время чиха — `G.sneezeAt`, не сохраняется). `playerLook()` у простуженной
  добавляет `sick: true` — рисунок (`art/hamster.js`) сам добавит красный нос, румянец и градусник; поза `sneeze`.
- `features/health.js` — всё, что видно: счёт неосторожностей (`step` — время в городе в холод и дождь без нужной
  одежды; события `swim` и `dive` — ледяное море), чих и звук, `planNight()` / `applyNight()` / `morningNews()`
  (их зовёт `features/sleep.js`: план — до `nextDay()`, применить — после, до письма дня), окна «Апчхи!» и «что
  делать» (`showSickHelp` — по значку 🤒 в HUD, `config.sick` в `ui/hud.js`), приём у доктора (действие `hospital`
  у здания больницы: простыла — доктор, иначе обычный вопрос медсестры `p.ask`; `health-tips` — «Как не простыть?»),
  отказ в работе: `sickAsk(p)` (действие `ask` в `places.js` убирает работу из ответов продавца) и проверка

- Вода: сцена «вид сверху» для простуженной пешком берёт правило прохода `map.noSwim` (клетки с `swim` закрыты;
  если она уже в воде — можно, чтобы выйти) и показывает подсказку, когда хомячок упирается в воду или нажали на неё;

- Частота считается в `dev/balance.js` (раздел «Болезнь»), автотест — `dev/smoke_health.js`.

## 4. События

`core/events.js`: `on(имя, fn)` → функция отписки; `emit(имя, данные)`; `scope()` — пачка подписок.

```js
const sub = scope();
enter()  { sub.on('guests', syncGuests); sub.on('wake', wake); }
leave()  { sub.off(); }
```

- Все имена перечислены в `EVENTS` с пояснениями. Подписка или `emit` с неизвестным именем — ошибка сразу.
  Новое событие сначала добавляют в `EVENTS`.
- Ежедневные задания (`features/mail.js`) считают прогресс по событиям: `buy`, `cook`, `talk`, `swim`,
  `visit`… Журнал сюжетных заданий (`features/quests.js`, раздел 13) — поверх тех же событий; для него добавлены
  `wear` (надели вещь), `herb` (сорвали для гербария), `quest` (задание взяли / сдвинулось / сдали), `land`
  (открылось место).
- `step` — шаг логики (игровые часы в `features/sleep.js`, гость-сюрприз в `features/friends.js`).
- `wake` — утро после сна: сцена-дом ставит хомячка у кровати. Спать можно в любом доме со своей кроватью.

Чего пока нет: планировщика «через N секунд игрового времени» (ревью, A5). Отложенные подсказки по-прежнему
на `setTimeout`.

## 5. Реестр действий

`core/registry.js` связывает «что случилось в сцене» с «что при этом происходит», не давая сценам
импортировать занятия.

```js
register('cafe', (p, ctx) => openCafe(p.kind, p.title || ctx.building.name), 'кафе: { kind, title? }');

run('bank');                                   // имя
run('minigame:chef');                          // имя:аргумент  → p = { arg: 'chef' }
run({ do: 'cafe', kind: 'rest', title: '…' }); // имя и параметры → p — этот объект
run(building.act, { building, back });         // ctx — кто вызвал
```

Действие записывают **в данных**:

| Где | Поле | Пример |
|---|---|---|
| здание локации (`buildings` в описании; у города — `BUILDING_ACTS` в `locations/town.js`) | `act` | `'scene:tower'`, `{ do: 'clothes-shop', vendor: 'mall', shops: ['mall'] }` |
| особое место локации (`places`) | `act` | `'mailbox'`, `'garden:3'`, `'fish:pier'` |
| житель локации (`actors`) | `act` | `'npc:myata'` (так по умолчанию) |
| находка (`pickups`), выход (`exits`) локации | `act` | необязательно: что сделать вдобавок / вместо перехода |
| встроенный предмет дома (`built` в описании) | `act` | `'cook'` |
| мебель (`data/furniture.js`) | `act` | `'sleep'`, `'wardrobe'`, `'piano'` |
| жилец дома (`actors` в описании) | `act` | `'npc:plusha'` |
| ответ в диалоге продавца (действие `ask`) | `do` | `'minigame:swim'` |

Что зарегистрировано сейчас (полный список с описаниями — `window.__dev.listActions()`):
`scene`, `ask`, `clothes-shop`, `home-mall`, `food-mall`, `cafe`, `market`, `bank`, `salon`, `panorama`, `minigame`,
`fish`, `npc`, `guest`, `mailbox`, `garden`, `surprise`, `cook`, `sleep`, `wardrobe`, `fridge`, `piano`, `soon`,
`hospital`, `health-tips` (больница и болезнь — раздел 3, «Болезнь»), `way`, `journal` (журнал заданий — раздел 13) —
и действия гостей, жилья и бизнеса (таблица в разделе 11): `home-of`, `host`, `say`, `telescope`, `bigfridge`, `oven`,
`realtor`, `home`, `home-exit`, `biz`, `my-biz`, `work`.

`market` — рынок (`'market'`, `'market:buy'` или `{ do: 'market', tab }`): прилавки на площади (здание `market`
в `locations/town.js`); продают только там.
`soon` — временная заглушка «Скоро открытие!» (`features/soon.js`) для мест, которые уже стоят в городе, но ещё
не открыты: `{ do: 'soon', key }` или `'soon:<ключ>'`. Ключ сейчас один — `hotel` (дверь здания — `BUILDING_ACTS`
в `town.js`). Когда занятие готово, у места меняют `act` на настоящее действие — так открылись агентство
(`'realtor'`), квартира (`'home:flat'`) и бунгало (`'home:bungalow'`).
`way:<место>` — вход в тайное место (лес, пустыня…; раздел 13): закрыто — доброе окно «кто знает дорогу», открыто —
сцена места из `LANDS`. `journal` — альбом на вкладке журнала заданий.
`ask` сам дописывает к вопросу продавца, сколько заплатят за работу и сколько оплачиваемых смен осталось,
если среди ответов есть `minigame:<игра с зарплатой>`.

Неизвестное действие — ошибка в консоли (автотест её поймает), игра не падает.

## 6. Окна

- `ui/panel.js` — `openPanel({ title, tabs, render, foot, onClose })`, `message({...})` → Promise с номером
  кнопки, `confirmBox(...)` → Promise<boolean>.
- `ui/dialog.js` — `dialog({ look, name, text, options })` → Promise с номером ответа.
- `ui/toast.js` — `toast(текст, 'good')`.
- `ui/modals.js` — **слои и очередь**:
  - всё, что закрывает сцену, берёт слой: `const close = openLayer({ dim, cover })` … `close()`. Пока открыт
    хоть один слой — мир на паузе. Счётчики `G.modal / G.dim / G.cover` руками не трогать;
  - окно, которое появляется само (подарок, рецепт, итог задания, смена сезона, клад), ставят в очередь:
    `enqueue(() => message({...}), { delay: 700 })`. Очередь показывает окна по одному и только когда экран
    свободен (плюс 250 мс паузы после закрытия предыдущего окна).
- `ui/hud.js` — плашки и кнопки. Правые кнопки задаёт `main.js`, левый столбик — `scene.hud()`.

## 7. Движок домов (`engine/side/`)

Дом — **описание** (обычный объект), сцена получается так: `createSideScene(описание)`.
Полный список полей — в начале `engine/side/scene.js`. Главное:

```js
export default {
  id: 'villa',                         // имя сцены
  floors: 3, width: 1600, lift: true,  // этажи, ширина жилой части, лифт справа
  rooms: [{ id, f, x0, x1, wall, floor: 'wood' | 'tile' | 'check', win: x | null, main: true }, …],
  built: [{ type: 'door', f: 0, x: 285 }, { type: 'kitchen', f: 0, x: 1225 }, …],   // встроенные предметы
  furniture: { key: 'villa', editable: true, keepOneBed: true },   // чья мебель — см. ниже
  door: { f: 0, x: 290 },              // где стоим, войдя с улицы
  exit: 'scene:world',                 // куда ведёт дверь; без exit — назад, откуда пришли
  persist: true,                       // сцена сохраняет свою позицию
  guests: { f: 0, enterX: 300, gap: 70, first: [420, 880], roam: [250, 1540] },   // сюда ходят гости
  actors: [{ npc: 'plusha', f: 0, x: 430, roam: [230, 840], act: 'npc:plusha' }], // кто здесь живёт
  shell: { wall, roof, chimneyX, bushes },                                        // дом снаружи
};
```

**Чья мебель** (`furniture`):

- `{ key, editable, keepOneBed, start }` — своя: лежит в сохранении (`'villa'` → `state.villa`, другие ключи →
  `state.homes[key]`), есть режим «Обустроить», кладовка общая (`state.storage`). `start` — что стоит
  в начале (создаётся при первом входе).
- `{ fixed: [[id, этаж, x, y?], …], noUse }` — чужая: стоит как в описании, в сохранение не попадает,
  переставить нельзя; чужой кроватью, шкафом и холодильником пользоваться нельзя.

**Какие дома это уже покрывает** (проверено пробным домом и автотестом):

| Дом из `docs/DESIGN.md` | Как описать |
|---|---|
| дом жителя: 2–3 комнаты, мебель фиксированная, хозяин внутри | `furniture.fixed`, `actors`, без `persist` и `exit` |
| покупное жильё: своя мебель, «Обустроить», кровать для сна | `furniture: { key, editable, start }`, `persist: true`, по желанию `guests` |
| холл и номера отеля | несколько этажей + `lift: true`; номера — комнаты; стойка — `built: { type: 'zone', act }` и `actors` |
| зал своего ресторана | один этаж, `furniture.fixed` (или своя мебель), `actors` с `act`, зоны с действиями |

Чего движок **не умеет** (понадобится — дописать в движке, а не в описании): лестницы (многоэтажный дом
без лифта), комнаты разной высоты, жильцы и гости не ездят между этажами, встроенные предметы имеют
фиксированный размер рисунка, свой рисунок стен и крыши (есть только крюк `art.back / art.front` для дорисовки).
Дверь в соседнюю сцену (номер отеля из холла) делается зоной: `{ type: 'zone', f, x, w, h, act: 'scene:…' }`.

## 8. Движок локаций (`engine/topdown/`)

Локация («вид сверху»: город, а дальше лес, гора, пещеры, пустыня…) — **описание** (обычный объект), сцена
получается так: `createTopDownScene(описание)`. Полный список полей и крюков — в начале
`engine/topdown/scene.js`; пошаговый рецепт — в разделе 9 («…новую локацию»). Образцы: `locations/town.js`
(большая карта правилами), `locations/demo_meadow.js` (маленькая карта картинкой — с неё удобно списывать).

```js
export default createTopDownScene({
  id: 'forest',                        // имя сцены; оно же в сохранении позиции: { scene: 'forest', x, y }
  title: 'Лес',                        // заголовок окна карты
  rows: ['TTTT', 'T..T', …], legend: { '.': 'g', T: ['g', 'tree'] },   // карта картинкой…
  // …или правилами:  w: 72, h: 106, build(m) { m.fill(0, 0, 71, 36, 'g'); m.add('tree', 5, 5); … }
  buildings: [{ id, kind: 'house', x, y, w, h, name, icon, wall, roof, act: 'scene:hut' }],
  places:  [{ id: 'well', at: [8, 4], hit: { dx: 30, up: 50, down: 20 }, stand: [8.5, 5.5], act: 'fish:pond' }],
  actors:  [{ npc: 'myata', at: [6, 5], home: 'hut' }],
  pickups: [{ id: 'berry', at: [16, 8], icon: '🍓', give: ['ing', 'strawberry', 1] }],
  entries: { gate: { at: [11, 11.5] } },
  exits:   [{ id: 'town', area: [10, 13, 11, 13], to: 'world', entry: 'forest' }],
});
```

**Что умеет сцена сама:** ходьбу по нажатию (поиск пути) и стрелками, «дойти и сделать», вход в здания,
особые места, жителей (днём гуляют, утром и вечером — у своих дверей, ночью спят; кто позвал в гости — уходит
домой и ждёт внутри: `engine/topdown/actors.js`), предметы заданий и находки, переходы между
локациями, камеру, погоду и ночь, указатель цели задания, мини-карту, сохранение позиции, HUD и звук.

**Из чего собрана карта — реестр видов** (`engine/topdown/kinds.js`). Три таблицы с общими на всю игру
именами: виды клеток (`defineTiles`), предметов (`defineObjects`), зданий (`defineBuildings`).

- Общие виды лежат в `locations/common/` и появляются в реестре от `import './common/index.js'`:
  - клетки (`tiles.js`): `g` трава, `r` мостовая, `k` брусчатка площади, `y` дорожка, `s` песок, `p` плитка,
    `i` доски, `I` снег, `h` мелководье, `w` глубокая вода (плыть), `O` открытое море (нельзя), `o` бассейн,
    `d` пруд (зимой каток);
  - предметы (`objects.js`): `tree`, `pine`, `palm` (без плодов), `bush` (замедляет), `flowers`, `fenceH`,
    `fenceV` (поле `v`: 0 — белый штакетник, 1 — деревянный), `bench`, `fountain`, `lounger`, `umbrella`,
    `starfish`, `crab`, `chest`, `flag`;
  - растения с плодами (`plants.js`): `cocoPalm`, `bananaPalm`, `mangoTree`, `berryBush` (черника, замедляет),
    `mushrooms`, `appleTree` (яблоня; город и лес). На обычных `tree` и `bush` плодов не рисуется — только цветение
    весной и пёстрые листья осенью, чтобы ребёнок не путал их с растениями, которые можно сорвать.
    Плод есть только в сезон продукта (`data/seasons.js`; у яблок, которые в магазине круглый год, — свой сезон
    сбора `PICK_MONTHS`, читать — `pickIn(id, месяц)`, `whenPick(id)`) и пока его сегодня не сорвали (отметка дня
    `dayFlags.plants`, наутро вырастает снова); с плодами и без — разные спрайты. Что на чём растёт и какие
    подписи — таблица `PLANTS` там же. Локация ставит их обычным `m.add(…)` и подключает часть
    `parts: [createPlants()]` — она показывает подпись «Сорвать…» над растением рядом с хомячком, кнопку в HUD,
    слушает клавишу E и рисует на мини-карте значки того, что сейчас в сезоне (крюк `miniMap`; близкие растения
    одного вида — одним значком, `fruitGroups`; подпись под картой — `ripeIcons()`, её показывает `features/map.js`); нажатие на само растение работает через `tap` + `use` вида;
  - уличная мебель и дворы (`props.js`): `lamp` (ночью светит), `flowerbed`, `hedge`, `planter`, `bin`,
    `signpost` (поля `text`, `text2`), `postbox`, `clothesline`, `hammock`, `swing`, `slide`, `sandbox`, `toys`,
    `ball`, `cafeTable`, `crate`, `barrel`, `picnicTable`, `bbq`, `ambulance`, `busstop`, `gate` и `barrier`
    (ворота и шлагбаум, поле `open()`), `anchor`, `rowboat`, `greenhouse`, `hoop`, `dumbbells`, `mannequin`,
    `globe`, `reeds`, `rock`, `towel`, `sandcastle`, `net`, `lifeguard`, `statue`;
  - здания (`buildings.js`): `house` (дом жителя; поля `shutters`, `smoke`, дорисовка `art`), `shop`, `mall`,
    `tower` — и «конструктор», из которого собраны здания города (`town_buildings.js`).
- Свои виды локация определяет в своём файле (город — грядку, почтовый ящик, лунку; море — буйки, айсберги,
  маяк, вулкан; полянка — клевер и валун). Имя клетки — любая строка (`'clover'`), не обязательно буква.
- От вида зависит и поведение: по клетке можно или нельзя ходить (`walk`, `block`), это вода (`wet`, `swim`),
  пляж (`beach` — песок и пирс: хомячок нарисована в шлёпанцах, если они есть, кроме зимы; `sc.heroLook()` в
  `scene.js` и `beachLook()` в `core/state.js` — только картинка, наряд не меняется),
  с какой скоростью и каким звуком по ней идут (`speed`, `step`); предмет занимает клетку (`solid`) или
  замедляет (`slow` — «медленные» клетки вроде кустов). Поля — в начале `kinds.js`.

**Кэш спрайтов** (`core/sprites.js`) у всех локаций один (`SP` из `kinds.js`). Неподвижные рисунки предмет
объявляет в поле `art` и ставит вызовом `put('имя', x, y, параметр, параметр)`; здания движок кладёт в кэш сам.
Правило «спрайт 1:1 на целых пикселях» держится на `cam.setTileZoom` (в `scene.js`) и `cam.pixelOrigin()`
(в `render.js`) — их не трогать. Размер клетки `T = 48` — один на все локации.

**Земля** (`engine/topdown/ground.js`) клетками каждый кадр не рисуется. Карта разбита на куски 4 × 4 клетки;
кусок один раз рисуется в свою картинку (в масштабе экрана, 1:1) и дальше копируется. Куски за краем экрана
готовятся заранее, по одному за кадр; в памяти остаются только экран и кольцо вокруг (4–6 млн пикселей), остальное
вытесняется. Сезон входит в ключ куска. Поэтому рисунок земли может быть сколько угодно подробным.

- Вид клетки — **слой**: поле `z` говорит, кто кого перекрывает (вода 0 → мелководье 1 → песок 2 → трава 4 →
  дорожка 5 → мостовая 6 → площадь 7 → плитка 8 → бассейн 9 → пруд 10 → доски 11). Слой вида — область «все клетки
  не ниже него»; её край скруглён (`edge.r`) и слегка неровен (`edge.wob`), так что квадратных ступенек между
  травой, песком и водой нет. Обводки края: `edge.out` — под слоем (тень на нижнем слое, бордюр, пена),
  `edge.in` — поверх (кайма травы, мокрый песок). `fill(env, ctx)` — цвет или градиент слоя, `deco(…)` — мелочи
  клетки (пучки травы, камешки, кувшинки), `live(ctx, cells, n, env)` — то, что шевелится: зовётся каждый кадр
  один раз на вид со списком видимых клеток (блики на воде — один путь на весь экран).
- Вид без `z` (один `draw`) по-прежнему работает: рисуется в кусок квадратом поверх слоёв (`anim: true` — каждый
  кадр).
- Крюк локации `paintGround(ctx, env, x0, y0, x1, y1)` дорисовывает в кусок неподвижное (разметку бассейна);
  крюк `ground(ctx, sc, env)` — то, что меняется, каждый кадр.
- Линия прибоя вдоль берега моря (клетки с `surf: true`) считается один раз на карту (`buildShore`) и рисуется
  двумя путями за кадр; под мостками (`bridge: true`) она прерывается.

**Свет и небо** (`render.js`). Время суток, ночная темнота, пятна света и тени облаков рисуются не в кадр, а в
отдельный слой — маленькую канву `#sky` поверх игры (примерно в 8 раз мельче экрана), которую растягивает
страница: кадр от этого не дорожает. Ночью (темнота > 0,3) темнота «прорезана» мягкими пятнами: их дают предметы
с полем `light: [dx, dy, радиус]` (фонарь) и здания, чей вид возвращает `lights(b) → [[x, y, rx, ry?, сила?], …]`
(окна, дверь, фасад; готовая функция — `facadeLights` в `common/buildings.js`). Окна в спрайте здания горят,
когда `lit` (параметр `paint`). Слой прячется, когда хомячок уходит из локации (`hideSky` в `leave`).
Бабочки (днём, весной и летом), светлячки (летними ночами), лужицы и круги на воде в дождь, дымок из труб —
там же; всё привязано к клеткам «случайным» числом клетки, без состояния.

**Поиск пути** (`path.js`) — чистые функции: кто где может пройти, говорит `pass(tx, ty)`, который передают
в вызов. Готовые: `map.foot` (герой пешком), `map.dry` (жители — только по суше). Свой способ передвижения —
поле героя `sc.p.ride = { speed, pass, step, moved, draw, drop }`: пока оно задано, герой ходит по его
правилам (так сделан кораблик в `sea.js`). Глобальных переключателей режима больше нет.

**Особые места** (`places`) — данные: где место (предмет с зоной нажатия `at + hit`, клетка `cell`,
прямоугольник `area` или все клетки вида `tile`), куда встать (`stand`), когда оно работает (`when`),
какое действие из реестра выполнить (`act`), как показать на мини-карте (`map`). Почтовый ящик, грядки, лунка,
пруд и пирс города записаны так (`PLACES` в `town.js`) — координат в коде движка нет.

**Переходы.** У локации есть точки входа (`entries`) и выходы (`exits`): хомячок наступил на клетку выхода →
`go(to, { at: entry })` → появился в точке входа другой локации. Выход можно держать закрытым (`off: true`
или `when()`), открыть — `getLocation('world').exit('forest').off = false`. Вход в дом — как раньше, зданием
с `act: 'scene:<дом>'`. Кто пришёл из сцены, названной во входе (`from: 'villa'`), встаёт на этот вход.

**Несколько локаций** (`scene.js`): `locations` — все по имени сцены, `getLocation(имя)`,
`currentLocation()` — где хомячок сейчас (пока он в доме — та, что снаружи), `homeLocation()` — главная
(`home: true`, город). Занятия берут локацию отсюда, а не импортируют город: окно карты (`features/map.js`)
показывает текущую локацию, почта (`features/mail.js`) разбрасывает предметы задания в локации задания
(`loc` в задании; без него — в главной) по её зонам (`zones`).

**Позиция в сохранении** — `{ scene: <id локации>, x, y }`. У города id — `'world'` (так записано в старых
сохранениях — **не менять**). Если позиция оказалась в стене (карту перерисовали), хомячок встанет на ближайшую
свободную клетку, а если её нет — на вход `start`.

**Части и крюки.** То, что у локации уникально, пишут функциями-крюками в описании: `built`, `enter`, `tap`,
`tapThing`, `interact`, `near`, `idle`, `update`, `surface`, `ground`, `things`, `over`, `overlay`, `miniMap`,
`target`, `buttons`. Большую самостоятельную механику выносят в «часть» — объект с теми же крюками в списке
`parts`. Так подключено море: `sea.js` → `createSea(настройки)` даёт кораблик, острова, морских жителей,
буйки и ныряние; город зовёт `sea.buildGround(m)` и `sea.buildObjects(m)` в своих правилах карты.

**Порядок вызовов `Math.random` в `update`** сохранён прежним (герой → жители → погода → море): от него
зависят снимки «до/после» (`dev/shots.js`). Карта строится при первом обращении к локации (вход, окно карты,
`randomSpots`) — тогда же жители получают случайную паузу.

Чего движок **не умеет** (понадобится — дописать в движке, а не в описании):

- клетка всегда 48 единиц, карта — прямоугольник; «этажей» и мостов над дорогой нет;
- карта после постройки не меняется (нельзя на лету заменить клетку или поставить предмет; закрытый проход
  делают выходом с `off`, сезонное — функцией `walk` у вида клетки или `when` у места);
- жители гуляют возле своего места и ходят домой; расписания по часам и походов в другую локацию нет;
- способ передвижения (`ride`) при переходе в другую локацию не переносится: кораблик живёт в море города
  и хранит одно место в сохранении (`state.boat`) — для моря другой локации нужен свой ключ (`key` в настройках
  `createSea`);
- общей «карты мира» со всеми локациями нет: окно карты показывает одну, текущую;
- звёздочка задания показывает цель только внутри своей локации (до выхода в нужную локацию не ведёт).

## 9. Как добавить…

### …новую локацию

Образец для списывания — `js/locations/demo_meadow.js` (110 строк, в нём есть всё перечисленное ниже).
Координаты в описании — **в клетках**: `[5, 9]` — клетка; там, где нужна точка (`stand`, `entries`, `mark`),
дробная часть — место внутри клетки: `15.5` — середина клетки 15.

1. **Файл и имя.** Создай `js/locations/<имя>.js`:

   ```js
   import { T, OUT, put, defineTiles, defineObjects, createTopDownScene } from '../engine/topdown/index.js';
   import './common/index.js';                    // общие клетки, предметы и здания
   export default createTopDownScene({ id: 'forest', title: 'Лес', … });
   ```

   `id` — имя сцены; оно попадает в сохранение, поэтому **придумай один раз и не меняй**.
2. **Карта.** Маленькую удобнее рисовать строками: `rows: ['TTTT', 'T..T', …]` и `legend: { '.': 'g',
   T: ['g', 'tree'], M: ['moss', 'mushroom', { v: 1 }] }` — символ → вид клетки и, если надо, предмет на ней.
   Большую — правилами: `w, h, base: 'g'` и `build(m)`, где `m.fill(x0, y0, x1, y1, 'r')`, `m.set(x, y, 'g')`,
   `m.add('tree', x, y, { v: 2 })`, `m.at(x, y)`, `m.clear(x, y)` (убрать с клетки то, что поставили раньше);
   для случайной зелени бери `seeded(число)` из `core/util.js`,
   а не `Math.random` (образец — `build` в `town.js`). Край карты обнеси деревьями или водой.
   `bg` — цвет за краем карты.
3. **Свои клетки** — `defineTiles({ moss: { map: '#5a8', step: 'step', z: 4.5, fill: (env) => '#5a8',
   edge: { wob: 6, in: [['#487', 6]] }, deco(ctx, x, y, tx, ty, env, rnd) { … } } })`. `z` — слой (между травой 4
   и дорожкой 5), `fill` — цвет, `edge` — край, `deco` — мелочи клетки (`rnd(i)` — постоянные «случайные» числа
   клетки); сезон — `env.season`. Подробности — раздел 8, «Земля»; образец — клевер в `demo_meadow.js` и все
   клетки `common/tiles.js`. Совсем простую клетку можно задать по-старому, одним `draw` (квадрат `T + 1`).
   «Такая же, как другая, но со своим правилом» — `like: 'y'` (так сделаны клетки под воротами в `town.js`).
   `map` — цвет на мини-карте. Нельзя ходить — `walk: false`; вода — `wet: true` (и `swim`, если хомячок в ней
   плывёт); своя скорость — `speed`. Буквы общих клеток заняты (раздел 8) — называй свои словами.
4. **Свои предметы** — `defineObjects({ mushroom: { solid: true, art: { mushroom: [[-20, -30, 20, 16],
   (ctx, season) => { …рисуем вокруг точки (0, 0) — центра клетки… }] }, draw(ctx, o, env) { put('mushroom',
   o.x, o.y, env.season); } } })`. В `art` — только неподвижное: рамка `[x0, y0, x1, y1]` с запасом и функция
   рисования; всё, от чего зависит вид (сезон, вариант `o.v`, «горит свет»), передавай параметрами `put` —
   они входят в ключ кэша. Шевелится — либо сдвигай готовый спрайт (`put('crown', o.x + Math.sin(env.t) * 1.5,
   o.y)`), либо рисуй линиями поверх после `SP.world()`. Рамка мала — в консоли будет предупреждение, автотест
   его ловит. `solid: true` — на клетку не встать; `slow: 0.5` — идут вдвое медленнее; `flat: true` — лежит
   под ногами; `tap` + `use(sc, o)` — можно нажать, `tapIf(o)` — когда именно (образец — растения с плодами
   в `common/plants.js`: дерево откликается всегда, грибы — только пока выросли).
5. **Здания** — `buildings: [{ id, kind, x, y, w, h, name, icon, wall, roof, act }]`: `x, y, w, h` — «пятно»
   в клетках, дверь снизу по центру, хомячок встаёт под ней. Дверь нарисована сбоку — у вида здания поле
   `doorX` (сдвиг от середины, единицы мира), а рисунок ставит дверь в `cx + doorX(b)`: тогда под дверью встают
   и хомячок (`map.doorPx`), и жители, и ночью там же пятно света (салон, бутик, кафе, агентство). `act` — что происходит на входе:
   `'scene:<дом>'` (дом — раздел 9, «…новый дом»), `'minigame:<id>'`, `{ do: 'ask', … }` и т. д.
   Нужен свой вид здания — `defineBuildings({ hut: { paint(ctx, b, snow, lit) { … }, box, lights } })`, рисуется
   в координатах мира от `b.x * T, b.y * T`. Собирай его из «конструктора» `common/buildings.js` (`geom`,
   `baseShadow`, `wall`, `roof`, `gable`, `win`, `door`, `steps`, `chimney`, `showcase`, `wallLamp`) и вывесок
   `common/paint.js` (`signBoard`: доска, табличка, неон, лента; `awning` — маркиза); образцы — все здания
   города в `town_buildings.js`. Рисунок выше «пятна» — задай рамку `box(b)`; свет ночью — `lights: (b) =>
   facadeLights(b, радиус, насколькоВыше)`.
6. **Жители** — `actors: [{ npc: 'shishkin', at: [6, 5], home: 'hut' }]`. `npc` — id из `data/npcs.js`
   (нового жителя сначала добавь туда: имя, внешность, реплики). Гуляет возле `at`, с 19:00 идёт к двери
   здания `home` (или в клетку `home: [x, y]`), ночью его нет (`always: true` — есть всегда). Подошёл
   хомячок — выполняется `act` (по умолчанию `'npc:<id>'` — разговор).
7. **Особые места** — `places: [{ id, …, act }]`. Где: `at: [x, y]` + `hit: { dx, up, down }` (нажимают
   на предмет, который ты поставил на эту клетку) либо `cell: [x, y]`, `area: [x0, y0, x1, y1]`, `tile: 'вид'`
   (нажимают на клетки). `stand: [x, y]` — куда хомячок встанет; `when: () => …` — когда место работает.
   `act` — действие из реестра (раздел 5): готовое (`'fish:pond'`, `'panorama'`, `'minigame:<id>'`,
   `{ do: 'cafe', … }`) или новое — тогда зарегистрируй его в своём файле `features/` («…новое действие»).
   Совсем простое можно написать на месте: `use(sc) { toast('Ку-ку!'); }` вместо `act`.
8. **Переходы.** В обеих локациях нужны вход и выход:

   ```js
   // в лесу                                              // в городе (locations/town.js)
   entries: { gate: { at: [11, 11.5] } },                 entries: { …, forest: { at: [2, 1.5] } },
   exits: [{ id: 'town', area: [10, 13, 11, 13],          exits: [{ id: 'forest', area: [1, 0, 2, 0],
            to: 'world', entry: 'forest' }],                       to: 'forest', entry: 'gate', off: true }],
   ```

   `area` — клетки, наступив на которые хомячок уходит; вход ставь **рядом с выходом, но не на его клетки**.
   Закрытое до задания место: `off: true`, а открывает его занятие — `getLocation('world').exit('forest').off =
   false` при загрузке и при выполнении задания (или `when: () => !!G.state.flags.forestOpen` прямо в описании).
   Переход «через действие» (канатная дорога с вопросом «Едем?») — особое место или здание с `act`, которое
   зовёт `go('mountain', { at: 'station' })`.
9. **Собираемое.** Находки локации — `pickups: [{ id, at: [x, y], icon: '🍄', give: ['ing', 'mushroom', 1],
   text: '+1 🍄 Гриб' }]`: лежат на земле, подбираются на ходу, утром появляются снова (`once: true` — один раз
   за игру). `give` — `[сумка, id, сколько]` для `addItem` (сумки: `ing`, `seeds`, `dishes`, `storage`); сам
   предмет сначала добавь в таблицу `data/`. Каждая находка шлёт событие `find { loc, id }` — по нему
   считают задания. Чтобы находки каждый день лежали в новых местах, в крюке `enter` вызови
   `sc.setPickups(sc.randomSpots('glade', 5, G.state.day).map((s, i) => ({ id: 'm' + i, at: [s.x, s.y], … })))`. Предметы ежедневного задания «собери»: опиши зону `zones: { glade: { x: [1, 18],
   y: [1, 12], tiles: ['g'] } }`, а в задании (`data/tasks.js`) укажи `loc: '<id локации>'` и `zone: 'glade'`.
10. **Мини-карта и «дойти до места».** Окно карты само показывает текущую локацию: землю красит полем `map`
    видов клеток, деревья — полем `map` видов предметов, здания — их цветом и значком. Кнопки «дойти» получают
    здания с `name`, точки `spots: { glade: { at: [8.5, 6.5], label: '🌼 Поляна' } }` и особые места
    с `map: { icon: '🎣', at: [51, 46], label: '🎣 Пирс' }`. Что-то своё на карте — крюк `miniMap(ctx, sc, k)`
    (`k` — пикселей на клетку). Звёздочка задания — крюк `target(sc)` → `{ x, y, icon }`; точку по имени
    даёт `sc.spot(id)` (образец — `target` в `town.js`).
11. **Свет, погода, звук.** Вечная зима на вершине — `season: 'winter'` (деревья и земля рисуются зимними
    в любой месяц). Под землёй или под крышей — `sky: false` (ни погоды, ни ночи). Пещера с фонариком:

    ```js
    sky: false,
    overlay(ctx, sc, w, h) {                       // поверх кадра, в экранных координатах
      const s = sc.cam.toScreen(sc.p.x, sc.p.y - 30);
      spotlight(ctx, w, h, s.x, s.y, 170);         // темнота с кругом света; spotlight — из engine/topdown/index.js
    },
    ```

    `sound: (sc) => ({ day: 'town', sea: 0, rain: 1, birds: true, crickets: true })` — что слышно.
12. **Уникальная механика** (кататься на верблюде, светлячки ночью, белка-меняла) — крюками в описании:
    `update(sc, dt)`, `things(sc, add, view)` — нарисовать своё в общем порядке «дальше → ближе»,
    `tapThing(sc, w, tx, ty)` — нажали на своё существо, `buttons(sc)` — кнопки HUD. Большое — отдельным файлом-
    «частью» (`parts: [часть]`), образец — `locations/sea.js`. Состояние меняй только действиями (раздел 3).
13. **Зарегистрируй** в `js/main.js`: `for (const loc of [town, demoMeadow, forest]) registerScene(loc.name, loc);`.
14. **Проверь.**

### Стиль графики мира (для новых локаций)

Чтобы новая локация выглядела «той же рукой», рисуй её теми же приёмами (`locations/common/paint.js`):

- **Контур** — тёплый тёмно-коричневый `OUT`, 2–2,5 единицы у крупных форм, 1–1,5 у деталей. У земли контуров нет:
  её границы — это края слоёв.
- **Объём** — 2–3 тона и блик, свет всегда слева сверху: `puff` / `crown` (кроны, кусты, снежные шапки — основной
  тон, тёмный серп снизу справа, светлое пятно сверху слева), `box` (блик сверху, тень снизу), `wall` и `roof`
  у зданий. Листва по сезону — `leafTones(сезон, вариант)` → [тёмный, основной, светлый].
- **Тень на земле** — `shadow(ctx, x, y, rx, ry)`: мягкий сиреневатый эллипс под предметом, чуть сдвинутый вправо;
  у зданий — `baseShadow`. Тень входит в спрайт предмета.
- **Сезоны** — параметром рисунка: зимой `snowCap` на всём, что стоит; весной цветы, осенью опавшие листья.
- **Вывески** — `signBoard(ctx, текст, cx, cy, w, h, вид)`: `'wood'` (доска — дома, указатели, пляж),
  `'plate'` (цветная табличка — магазины), `'neon'` (ночью светится — ресторан, отель), `'banner'`.
- **Земля** — новый вид клетки: `z`, `fill`, `edge`, `deco` (раздел 8). Палитра земли — `PAL`; мелочи рисуй
  приглушённо (полупрозрачные пятна, пучки травы тоном темнее), иначе земля спорит с предметами.
- **Свет** — фонарю достаточно поля `light`, зданию — `lights`; тёмная локация (пещера) — `sky: false` и свой
  `overlay` со `spotlight`.
- **Скорость** — всё неподвижное в спрайт (`art`) или в кусок земли (`deco`, `paintGround`); каждый кадр — только
  то, что шевелится, и по возможности одним путём на весь экран (образцы — `seaLive`, `drawSurf`,
  `drawButterflies`).

### …вид с башни

Панорама с площадки Хомяк-Тауэра и картинка в подзорной трубе рисуются одним кодом — `interiors/tower_view.js`.
Город там описан в клетках карты (`VIEW_TOWN` — здания, рядом списки улиц, прудов, островов): башня смотрит
на юг, поэтому восток слева, а чем южнее, тем дальше. Слоёв шесть (`VIEW_LAYERS`): небо, море с островами, пляж
и набережная, дальние кварталы, площадь, крыши у башни; у слоя — своя скорость сдвига при ходьбе (`par`) и своя
дымка (`haze`: дальние светлее и голубее). `renderViewLayer` рисует слой в отдельную картинку; площадка
(`drawView` в `tower.js`) держит шесть картинок в размер экрана и каждый кадр только копирует их со сдвигом
на целые пиксели. Перерисовка — при смене сезона, времени суток (темнота идёт ступеньками, по слою за кадр)
или размера экрана; вживую рисуется лишь то, что шевелится (`paintViewLive`: облака, кораблики, кит). Слои
идут от дальнего к ближнему, внутри слоя — тоже (сортировка по ряду карты), так что дальнее никогда не
перекрывает ближнее. Новая примета города — строка в `VIEW_TOWN` или вызов `at(x, y, …)` в `city`.

**Жильё и город.** В свой дом входят только через дверь: здание в городе (или лифт башни) зовёт `home:<id>`
и передаёт `back` — место у двери; `home-exit` возвращает туда же. Какое здание — дверь какого жилья, записано
дважды и должно совпадать: `BUILDING_ACTS` в `locations/town.js` (`home_apartment: 'home:flat'`) и поле `building`
в `HOMES` (`data/estate.js`) — по нему кнопка «Домой» (`askGoHome` → `goToHome`) выводит дверь основного дома
к двери его здания, а «Идём туда!» после покупки ведёт хомячка к этой двери (`walkToPlace`).

**Жители дома и на улице** (`engine/topdown/actors.js`, часы — `VISIT`). Днём житель гуляет у своего места;
утром до 9:00 и вечером с 19:00 (когда к нему можно зайти) — у своей двери; если он позвал в гости
(`invitedToday`: «Заходи ко мне сегодня!» или хозяин дня из прочитанного письма «день гостей» — `guestsWaiting()`
в `core/state.js`, кто именно — `guestHosts(задание, день)` в `data/tasks.js`: `host` или `hosts` жителей по жребию дня)
— идёт к двери, «заходит» и до конца дня на улице не показывается (`n.inside`); при входе
в локацию жители расставляются по местам (`settleResidents`).

**Таблички «моё» в городе.** У купленного заведения и купленного жилья на здании висит табличка (`things`
в `locations/town.js`: `drawOwnBiz`, `drawOwnHome`). Она рисуется каждый кадр поверх спрайта здания — кэш спрайтов
не трогается. Своё название заведения — на большой вывеске самого здания: у зданий заведений город ставит поле
`signText()` (название из `state.biz[id].title` или `null`), движок кладёт его в ключ спрайта здания (`drawBuilding`
в `render.js`), рисунки зданий (`town_buildings.js`) пишут его вместо `name`; длинное — в две строки (`fitLines`,
`signBoard(…, wrap)` в `common/paint.js`). Переименовали — ключ другой, картинка перерисуется сама.

**Как заведение узнаёт себя.** Город про заведения не знает: окна и диалоги заведений (`cafe`, `ask`, `salon`,
`clothes-shop`) спрашивают `bizByVendor(продавец)` из `features/business.js`. Если продавец — хозяин заведения
из `BUSINESSES`, в окне появляются табличка (`bizSign`) и кнопки (`bizFoot`), в диалоге у двери — вариант
«Купить заведение» / «Моё заведение» (`bizAskOption`). Работа хозяйки — мини-игра из поля `game`; хозяйке
платят больше и растёт выручка дня — это считает `features/minigames.js` (`jobToday(id, biz)`, `markBizWorked`).

**Движок домов: что добавилось** (подробно — в начале `engine/side/rooms.js`, `fixtures.js`, `items.js`):
обои `paper: 'dots' | 'flowers' | 'stars' | 'waves' | 'diamonds' | 'brick' | 'logs'` (брёвна) `| 'open'` (терраса), пол `'deck'`;
окна `win: x | [x, …]`, `winW` (панорамное), `view: 'sea' | 'city' | 'forest'`; дом снаружи —
`shell: { flat, trees: 'palm' | 'fir', ground: 'sand' | 'tower' }`; у встроенных предметов — цвет `c`
и `acts: { зона: действие }`; у мебели — действия `spin`, `look`, `water`, `sport` и подпись `say`;
поле `owner` в описании — чей дом. Свой дом (`persist`) кладёт в сохранённую позицию поле `out` — куда ведёт дверь.

## 12. Что дальше

Этап 4 из `docs/DESIGN.md` (гости, жильё, бизнес) сделан — раздел 11. Каркас готов для этапа 5: дома строятся
описаниями для «движка домов» (раздел 7), места — описаниями для «движка локаций» (раздел 8). Что остаётся сделать
по мере надобности:

- **Новые локации** (гора, пещеры, пустыня, джунгли, секретный пляж, удалённый остров, отель) — по рецепту
  из раздела 9; лес сделан — образец тайного места (раздел 14). В городе есть остановка каравана в пустыню (выход
  `desert`), в лесу — станция канатной дороги на гору (`way:mountain`); общий стиль рисования — «Стиль графики мира»
  в разделе 9.
- **Карта мира.** Окно карты показывает одну локацию (под картой города — «Тайные места» с замочками, раздел 13).
  Звёздочка задания пока ведёт только внутри текущей локации; чтобы вела «через выход» в нужную, у каждой локации
  есть `exits` и `sc.whereIs(имя)` — этого достаточно, чтобы построить путь.
- **Задания в других локациях.** Журнал заданий готов (раздел 13): шаг задания с `where` в другой локации пока
  звёздочкой не показывается (нужна «карта мира»), но засчитывается по событиям где угодно; находки шлют `find`.
- **Кораблик в другую локацию** (джунгли, удалённый остров): море — часть локации (`createSea(настройки)`
  в `sea.js`), но кораблик хранит одно место (`state.boat`) и при переходе не «переезжает». Для причала
  в другой локации — выход на клетках воды и своё место кораблика там (`key` в настройках моря).
- **Праздники** — слой поверх локации («с такого-то по такой-то день добавить эти предметы»): карта после
  постройки не меняется, так что слой — это крюки `things` / `ground` в отдельной «части» (`parts`) либо
  доработка движка (перестроить карту при смене дня).
- Планировщика «через N секунд игрового времени» по-прежнему нет (ревью, A5): отложенные подсказки —
  на `setTimeout`.

**Состояние** (сохранение v5): `quests` — `id → { day, n: { шаг: сколько }, got: { шаг: [что] }, done: день | null }`,
`lands` — `id места → день открытия`, `finds` — сумка находок. Меняют только действия `takeQuest`, `questCount`,
`finishQuest`, `openLand` (и `addItem('finds', …)`); читают `questNow(id)` → `{ status: 'locked' | 'ready' | 'active'
| 'done', i: текущий шаг, steps: [{ have, need, ok }] }`, `questBadge(житель)` → `'!' | '?' | null` (кэш до
следующего изменения состояния — сцены зовут каждый кадр), `findsWanted(kind)`, `landOpen(id)` — всё в `core/state.js`.

**Как добавить задание** — одна запись в `QUESTS`:

1. `id` (в сохранение — не переименовывать), `npc` (кто даёт; над ним «!»), `icon`, `title`, `story`, `when(s)` —
   когда можно взять (без него — сразу), `lines` — `offer`, `accept`, `later`, `wait` (по номеру шага), `done`.
2. `steps` — шаги по порядку. Виды шага:
   - `{ on: 'событие', n, if: { поле: значение }, min: { поле: число }, distinct: 'поле' }` — «сделать»: событие из
     `core/events.js` случилось `n` раз. Примеры: `{ on: 'minigame', if: { id: 'swim' }, min: { stars: 3 } }`,
     `{ on: 'buy', if: { id: 'flashlight' } }`, `{ on: 'wear', if: { slot: 'head' } }`, `{ on: 'harvest' }`,
     `{ on: 'scene', if: { name: 'tower' } }`, `{ on: 'talk', n: 3, distinct: 'id' }` (с тремя разными);
   - `{ bring: { bag, id } | { bag, kind, distinct: true }, n }` — «принести»: смотрит в рюкзак (не считается
     по событиям); отдаётся, когда задание сдают;
   - `{ talk: 'житель', btn, say }` — «поговорить» (над жителем «?»); последний шаг — сдать задание.
   У шага `text` (для журнала), `hint` («куда идти» словами) и `where` — куда звёздочка: здание, место, точка
   локации, `'npc:<житель>'` или имя, которое знает крюк `where` части локации (`'herb'`).
   Шаги «сделать» засчитываются в любом порядке с той минуты, как задание взято; «поговорить» — когда всё до
   него сделано. Нужного события нет — добавь его в `EVENTS` и пошли там, где это естественно случается
   (действие или занятие), а не опрашивай состояние в кадре.
3. `reward` — `coins` (число — в `QUEST_COINS`, `economy.js`), `sticker` (строка в `EXTRA_STICKERS`, `tasks.js`),
   `clothes` (вещь; если уже есть — `QUEST_GIFT_COINS`), `open` (id места из `LANDS`).
4. Больше ничего не нужно: значки, разговор (его зовут `npcDialog`, `guestDialog`, `hostDialog` через `questTalk`),
   журнал, плашка, звёздочка и окно «Задание выполнено!» берут всё из записи. Проверка — `node dev/balance.js`
   (награды, находки) и шаги в `dev/smoke_quests.js` по образцу Мяты.

**Тайные места.** `LANDS` в `data/places.js`: `name`, `icon`, `npc` и `who` (кто знает дорогу), `quest`
(задание-открытие или `null` — его ещё нет), `door` (первая фраза у входа), `at` (где вход словами), `scene` и `entry`.
Вход из города — особое место с `act: 'way:<место>'` (`PLACES` в `town.js`, на карте `map.lock` — замочек), выход —
`landExit(…)` там же. Окно `way` (`openWay` в `features/quests.js`): закрыто и задания нет — «дорогу откроют в одном
из следующих обновлений»; рано (`when`) — «загляни завтра»; можно взять — «поговори с …»; в работе — «всё в журнале»;
открыто — переход в `scene` или, пока сцены нет, окно `ready`.

**Лес подключён так** (образец для следующего тайного места): в `LANDS` у `forest` — `scene: 'forest', entry: 'gate'`;
выход `forest` из города (`landExit` в `town.js`) ведёт в сцену леса, как только лес открыт (`landOpen('forest')`),
ворота распахиваются, нажатие на ворота (`way:forest`) переводит туда же. Выход из леса — на вход города `forest`
(клетка за воротами). Шаг автотеста «переход между локациями» открывает лес действием `openLand('forest')`.

**Тайное место — что сделать следующему** (гора, пещеры, пустыня…): 1) сцена по рецепту (раздел 9) и регистрация
в `main.js`; 2) в `LANDS` — `scene` и `entry` (для горы вход уже стоит: станция канатной дороги в лесу, здание
`station` с `act: 'way:mountain'` — впиши сцену, и окно с замочком сменится переходом); 3) задание-открытие в `QUESTS`
с `reward.open` и строкой `quest` в `LANDS` (у горы — Сеня); 4) свой житель — строка в `LAND_NPCS` (`data/npcs.js`):
он не «друг» города (дружбы, гостей и домика в городе нет), разговор — своё действие (как `forester`), задания —
через `questTalk`; 5) задание внутри места — `loc: '<сцена>'` (журнал пишет «найди его в лесу», звёздочка ведёт
внутри локации); 6) шаги автотеста по образцу `dev/smoke_forest.js`. Звёздочка из города в другую локацию пока
не ведёт (нужна «карта мира», раздел 12): журнал подсказывает словами.

Поля, которые появились в журнале с лесом: у задания `loc`; в награде — `recipe` (секретный рецепт) и `hint`
(строка «что дальше» в окне «Задание выполнено!»). Знакомство в разговоре о задании не трогает дружбу, если житель
не из города.

**Гербарий** (`common/herbs.js`): `createHerbs([[вид, x, y], …])` в `parts` локации; вид — `flowers`, `tree`, `pine`
(предмет в этой клетке уже должен стоять). Место работает, пока `findsWanted('herb')`; раз в день (`dayFlags.herbs`);
одинаковую находку второй раз не даёт. Находка — `addItem('finds', id)` и событие `herb`. В другой локации — так же.
